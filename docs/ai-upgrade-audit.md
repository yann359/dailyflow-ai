# AI 模型中心升级检查与验收

## 已有实现与本次增量

原项目使用 Next.js 16 / React 19，IndexedDB（Dexie）保存本地饮食、训练、习惯、身体数据和备份；已有 OpenAI Responses、营养标签识别、饮食文字草稿、统计规则、AI 访问口令及 Redis 请求次数限制。之前只有一个 OpenAI 模型，缺少管理员身份、模型能力管理、费用预留、请求去重和多服务商路由。

本次保留原数据库表、索引、主键、备份版本与数据初始化过程。只增加可选 AI 偏好与对话模型字段，不重建数据库，不更新既有营养快照。原网站主题、导航、训练计划和手动记录流程保持兼容。

仓库：`https://github.com/yann359/dailyflow-ai`，现有 main 分支与 Vercel 自动部署关联。现有网站：`https://dailyflow-ai-zeta.vercel.app`。2026-10-11 只读核对 Vercel 的项目环境变量页，显示 **No Environment Variables Added**。未读取任何密钥值，未创建新仓库；本地验收通过后，用户已明确确认提交到现有仓库并部署现有项目。

## 实施阶段

1. 服务端：统一六种生成/测试/列表方法，分别处理 Responses、Messages、Google SDK 与兼容协议；维护官方验证的模型种子，动态发现的新模型不自动宣称图像等能力。方舟使用管理员登记的账号可用模型或推理端点 ID。
2. 设置页：独立模型中心、六家卡片、密钥配置状态、连接错误、任务分配、管理员能力/单价配置、持久化配置、管理员自定义接口。用户非秘密偏好保存在原设置记录中。
3. 功能：自然语言流式教练、食物照片估算草稿、标签识别、结构化每周复盘、真实训练组与身体趋势上下文。所有记录变更仍由用户确认；AI 不自动修改训练计划。调用前向用户显示具体服务商并确认必要数据；备用服务也必须逐一包含在授权中。
4. 安全：一小时 HttpOnly / SameSite 会话与管理员角色；独立强口令、服务端限流、请求字节限制、图片真实格式/尺寸限制、超时、无自动 SDK 重试、请求去重、Redis 原子预算预留、Token 与估算费用分别统计、SSR​​F 域名白名单和 DNS 结果绑定。无访问保护、无服务商密钥或缺少生产 Redis 时停止付费 API。
5. 发布：用户已确认，提交至上述现有仓库，由现有 Git 集成触发上述 Vercel 项目的部署；部署结果另行核对报告。未配置真实密钥与生产 Redis 时，线上付费 AI 继续关闭。

## 真实验证范围

六家服务商均 **未配置真实凭证、未完成真实 API 验证**。接口合同、错误处理、流式与结构化输出使用 Mock；浏览器 AI 流程使用 Mock 响应，不代表模型已连通。真实测试按钮只有服务端调用成功才写入连接成功状态，显示模型与测试时间。无凭证时不得显示连接成功。

正式上线还需要：用户配置 Vercel 环境变量和 Redis、管理员维护账号实际可用的模型 ID / 能力 / 当前单价，随后完成至少一家真实连接、聊天、流式、图片及周报验收。Redis Lua 使用事务语义编写；没有真实 Redis 凭证，尚未完成 Upstash 实网验证。
